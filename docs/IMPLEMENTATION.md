# 实现细节与设计取舍

> 本文是 [README](../README.md) 的补充，记录适配过程中的技术决定、踩过的坑与验证方法。
>
> **注意**：文中路径按作者开发时的目录结构书写（侧车在 `plugin/`、后端在 `audiocpp/`）。
> 在本仓库里侧车位于 [`server/`](../server/)，后端需要自行准备（见 README）。

本插件派生自 [Thirteen-Moons/ST-indexTTS2-X-Player](https://github.com/Thirteen-Moons/ST-indexTTS2-X-Player)
v1.2.7（commit `aadc9ca`，**AGPL-3.0**）。按 AGPL-3.0 要求，原始版权声明与 LICENSE 均完整保留。
上游原版插件（`ST-indexTTS2-X-Player`）仍独立存在，本插件与其**完全隔离、可同时启用**。

---

## 与原版的区别

| 方面 | 原版（IndexTTS2） | 本插件（Breeze TTS 2） |
| --- | --- | --- |
| 后端 | IndexTTS2 `api.py`，端口 7880 | Breeze sidecar，端口 **7881** |
| 情感控制 | 8 维情感向量（`emo_vec`）+ 固定情绪词表 | **大模型自由生成的自然语言描述** → 直接作为 `instruction` |
| 逐字稿 | 不需要 | **必需**（克隆时逐字稿必须与参考音频完全一致） |
| 音色/向量/LoRA | 有 | 无（Breeze 不支持） |
| 情感强度 | `emo_weight` | `guidance_scale`（默认 4，越大情绪越强、越慢） |

### 情感机制的核心改动

原版让大模型从**固定词表**里挑一个情绪词，再映射成 8 维向量。
Breeze 的合成指令本来就是自然语言，所以本插件改为让大模型**直接描述**该怎么念：

```
[小明][语气轻快上扬，带着藏不住的笑意，语速偏快][春日公园]“今天天气真好呢。”
```

第二个方括号的内容原样透传给 Breeze，情绪表现力的上限从「30 个词」变成「任意描述」。

### 旁白（叙述）也会被朗读

叙述、环境描写、心理活动必须**单独成行并带方括号**，角色名固定写作 `旁白`：

```
[小明][语气轻快上扬，带着笑意][春日公园]“今天的天气真好呢。”
[旁白][平静客观的叙述语气，语速适中，吐字清晰，情绪平稳][春日公园]“他悠闲地在公园中漫步，看着来往的人群。”
```

提示词里已为旁白写好默认描述（`平静客观的叙述语气，语速适中，吐字清晰，情绪平稳`），
允许按场景气氛微调，但不允许留空。

> **旁白同样需要在配音配置面板里绑定音色**，否则该行会被跳过——
> 见下方故障排查第一行。

### 新出场的角色（NPC）会自动分配合适的音色

大模型创造新角色时，插件会自动在配音配置里为它建一条目（音色为空）。
原版逻辑下**所有未绑定角色共用同一个回退音色**，等于全部 NPC 一个嗓子。

本插件改为**按性别-年龄段语义分配**：

1. 提示词要求大模型给每个角色名标注性别-年龄段，例如
   `[中年车夫|男-中年][语气粗粝，语速偏慢][集市]“客官，坐稳了。”`
2. 插件按标签从**对应的标签文件夹**里挑音色
3. 没有同标签音色时，用打分挑最接近的（性别 +2 / 一致年龄 +2 / 相邻 +1）
4. 标签也缺失时，退回按角色名哈希——**同名永远同音色**

**音色按标签文件夹组织**（`plugin\voices\` 下）：

```
男-儿童  男-少年  男-青年  男-中年  男-老年
女-儿童  女-少年  女-青年  女-中年  女-老年
中性-未定
```

放音频进对应文件夹即可，逐字稿用同名 `.txt`。详见 `plugin\voices\_说明.md`。

| 要点 | 说明 |
| --- | --- |
| 显式绑定优先 | 在配音配置面板绑过音色的角色，忽略标签 |
| 根目录音色不参与 | 根目录（无标签）的音色留给主角，避免 NPC 抢主角的声音 |
| 同角色稳定 | 同一会话内，同一角色永远分到同一个音色 |
| 文件夹为空 | 退化为全库打分，不会没声音 |

**设置**（配音配置面板顶部）：

| 控件 | 说明 |
| --- | --- |
| 未绑定角色自动分配音色 | 关掉即回到原版行为（全部共用回退音色） |
| NPC 音色池 | 逗号分隔的音色文件名，**手动指定候选**；留空 = 用所有带标签的音色 |

> 标签由大模型根据剧情判断，因此比关键词匹配准得多——它知道"行商少女"是女的。
> 但**池子的构成决定上限**：某个标签下没有音色时，只能退而求其次。

#### 自动分配必须"全程带着标签"

分配决策依赖台词里的 `[角色名|性别-年龄段]`。**任何一条调用路径漏传标签，都会退化成
「全池按角色名哈希随机」**——不看性别年龄。而缓存是按**角色名**做的键，所以只要有一次
无标签调用把结果写进缓存，这个角色的音色就被永久定死，之后播放时即使传了标签也失效。

修过一个正是这样的 bug：配音面板渲染角色列表时调用了 `resolveNpcVoice(名字)`（漏标签），
而那个调用的结果**在界面上根本不显示**——它只用来决定要不要画一行提示文字。也就是
「打开一次配音面板」这个纯查看动作，会悄悄把当次所有角色的音色随机定死。

现在三条规则保证不会再犯：

| 规则 | 作用 |
| --- | --- |
| 三个调用点（面板 / 行内播放 / 队列播放）**全部传标签** | 决策依据一致 |
| **无标签的分配不写缓存** | 临时查询不会污染长期结果 |
| 面板用 `commit: false` **只查询不提交** | 查看配置这个动作零副作用 |

配套改动：`getMergedCharacterList()` 以前只返回角色名、把 `parseVNLine` 解析出的
`voiceTag` 丢掉了，现在返回 `{name, tag}`；行内台词的 span 也新增 `data-g` 把标签
带到点击播放那一层（以前只带角色名，所以点一次行内播放同样会污染）。

> 实测对照：同一个角色 + 同一个 `女-少年` 标签
> - 直接播放 → `女-少年/女少03.wav`
> - 先开一次面板再播放 → 修复前 `女-老年/女老02.wav`，修复后**同样是 `女-少年/女少03.wav`**

### 音频间隔：让台词之间不再"抢话"

原版有两个**按解析模式分开**的延迟字段（`galSentenceDelay` / `rpSentenceDelay`），
默认留空等于不延迟，而且**听书模式完全没有**。结果是上一句刚播完、下一句立刻接上：

```
实测（流式路径、默认不延迟）：相邻两句之间只有 54ms
```

Breeze 合成很快（参考音频缓存命中后单句约 0.5 秒），所以"没有间隔"就会变成**首尾相接**，
听起来像两个人在抢话。现在统一成一个全局设置：

| 控件 | 默认 | 说明 |
| --- | --- | --- |
| **音频间隔** | 0.25 秒 | 相邻两句之间的停顿，**所有模式生效**（含听书模式） |
| **换角色额外间隔** | 0.35 秒 | 只在**说话人变了**的时候额外再加这么多 |

也就是：同一角色连着说话停 0.25 秒，换人时停 0.6 秒。

**关于"最小间隔"**：流式播放时下一句可能还没合成好，这时的等待本身就是停顿。
所以实现上保证的是**最小间隔**——实际停顿 = `max(设定值, 等待下一句合成的时间)`，
不会出现"等合成 + 再等间隔"的双重空档。

> 旧版的按模式延迟字段已移除，但**首次升级时会自动迁移**：
> 若你之前设过 `galSentenceDelay` / `rpSentenceDelay`，它的值会成为新的「音频间隔」。

三条播放路径都接入了这个设置：队列播放（`playTrack`）、流式播放（`playNextAudio`）、
以及跨消息自动续播（`autoPlayMessage`，原版这里完全没有间隔）。

## 安装与启动

用户视角的步骤见 [README](../README.md#快速开始)。这里只记开发时的两条命令。

### 1. 启动 Breeze 后端（端口 7870）

用整合包就双击 `启动后端.cmd`。自己搭则按上游 [breezeblue-ai/breeze-tts](https://github.com/breezeblue-ai/breeze-tts)
的说明起 `audiocpp`（GGUF）或 PyTorch 版，监听 `127.0.0.1:7870`。

### 2. 启动 sidecar（端口 7881）

```bash
cd server
python breeze_api.py                  # 默认数据目录就是当前目录
python breeze_api.py --data-dir <dir> # 想把音色库放到别处
```

音色库管理页：<http://127.0.0.1:7881/>

### 场景音效放在哪

放在**数据目录**的 `pjy/` 下（默认与 `breeze_api.py` 同级；整合包里是 `data/pjy/`）：

```
<数据目录>/pjy/
├── 环境音效/     循环播放，例如 雨声.ogg、森林.ogg
└── 事件音效/     只响一次，例如 房间_开门.ogg、敲门.mp3
```

**子文件夹决定播放方式**，提示词不需要为此做任何改动——模型照常写 `[敲门]`，
插件从 sidecar 拿到"这个文件在哪个子目录"，据此选择行为。

| | 环境音效 | 事件音效 |
| --- | --- | --- |
| 来源目录 | `环境音效/`（`pjy/` 根目录也算） | `事件音效/` |
| 循环 | 是 | 否 |
| 与上一个音效的关系 | **顶替**它（交叉淡化） | **叠在它之上**，环境音继续播 |
| 播完之后 | 继续循环 | 自动消失 |
| 音量设置 | 环境音音量 | 事件音音量（独立） |
| 重名时 | 环境音优先 | — |

> 事件音在**环境音的连续性上是透明的**：中间夹一行 `[敲门]` 不会把
> 「乡村清晨…乡村清晨」切成两段，环境音不会因此停掉再淡入重来。
> （这点专门修过——否则事件音越密，环境音重启越频繁。）

**三条硬性要求**，不满足就静默无声（不会报错，只是没声音）：

1. **文件名必须与提示词里的场景标签完全一致**，例如 `雨声_室内.mp3` 对应 `[雨声_室内]`
2. **区分大小写**。`女性轻微呻吟.MP3` 匹配不上，必须是 `.mp3`
3. 后缀只认 `.mp3 / .wav / .ogg / .m4a / .aac / .flac`

sidecar 提供两个端点支撑这个功能（`api.py` 时代就有环境音那份，移植到 Breeze 时漏了，已补上）：

| 端点 | 作用 |
| --- | --- |
| `GET /api/v1/scene_audios` | 返回两个目录的文件清单 + 每个文件在 `pjy` 下的相对路径 |
| `GET /pjy/<子目录>/<文件名>` | 静态托管音频本身（直接作为 `<audio>` 的 src） |

> 提示词里**列出**了某个场景、但两个目录里都没有对应文件时，模型仍可能选中它，
> 结果就是这一段没有音效。所以新增场景时，**列表和文件要一起加**；
> 不加文件就把标签从提示词里删掉。`setup\verify-all.py` 有一项检查会核对这个一致性。
>
> 顺带一提：**根目录的文件也算环境音**，所以把文件丢在 `pjy/` 根下不会报错，
> 但会被当成循环的环境音处理——事件音一定要放进 `事件音效/`。

#### 怎么让环境音停下来

环境音是循环的，所以「什么时候停」得说清楚。**五条停止路径**：

| 触发 | 说明 |
| --- | --- |
| **悬浮组件的环境音按钮（🎵）** | 点一下静音、再点恢复；悬停出滑块细调；右键原位输入数值 |
| 场景标签**留空** `[]` | 提示词里已明确要求：环境不在列表里就写 `[]` |
| **暂停播放** | 环境音随台词一起暂停，继续时一起恢复 |
| 每条消息播放结束 | 自动淡出 |
| 切换聊天 | 自动停止 |

**悬浮组件上的人声与环境音是两个独立控件**：

| 控件 | 图标 | 设置项 | 影响谁 |
| --- | --- | --- | --- |
| 人声音量 | 🔊（音量低/静音时换图标） | `volume` | 只影响台词 |
| 环境音音量 | 🎵（静音时变 🚫） | `ambientSoundVolume` | 只影响环境音 |

两者**互不干扰**：静音环境音时台词照常播，静音台词时环境音照常响。
实测音量序列——环境音 `[0, 0.5, 0, 0.5, 0.2]` 依次对应「淡入 → 设定值 → 静音 → 恢复 → 拖滑块」，
期间台词音量恒为 `1`。

> 事件音没有单独的悬浮控件——它很短，很少需要一边听一边调，用设置面板里的
> 「事件音音量」就够了。

> **为什么提示词要专门写一句 `[]`**：如果模型遇到列表里没有的环境而随手写个近似词，
> 插件找不到文件，就会让**上一个环境音继续响下去**——你会听到上一个场景的声音留在新场景里。
> 留空是唯一干净的"这里没有环境"信号。
>
> 实测过 `[ ]`、`[]`、以及干脆省略第三个方括号，三种写法都能正确停掉环境音。

#### 淡入淡出（切换场景时怎么过渡）

设置面板「场景音效」里的**淡入淡出**控制场景切换的交叉淡化：旧音效淡出、新音效淡入。
**默认是「关闭」**，此时切换是硬切。

> **修过一个 bug**：淡入淡出的 rAF 句柄原本是**单个全局变量**。切换比淡出更快时
> （例如事件音效密集出现），新的淡出会取消掉上一个元素还在跑的淡出——那个元素
> 既不会 `pause()` 也不会清 `src`，而它是 `loop = true` 的，于是**永远以中间音量循环播放**。
> 实测：三句各换一个场景 + 淡出 800ms，前两个音效全被搁置在音量 0.06。
>
> 现在 rAF 句柄挂在音频元素自己身上，同一元素上的淡入/淡出也会互相取消。
> 修复后同样的测试：被搁置 2 个 → **0 个**。

### 3. 在插件设置面板确认三个地址

| 设置项 | 默认值 |
| --- | --- |
| TTS 服务地址 | `http://127.0.0.1:7881/tts` |
| 音色克隆地址 | `http://127.0.0.1:7881/api/v1/breezetts2_cloning` |
| 音频列表地址 | `http://127.0.0.1:7881/voices` |

### 4. 准备音色

**上传参考音频**：在音色库管理页 <http://127.0.0.1:7881/> 上传。建议 6–10 秒、干净、情绪平稳、无背景噪音。
页面会做响度体检（偏响的参考会让所有输出都像在喊）。

音色名**可以用中文**（如 `旁白.wav`）。Breeze 运行时是 C++，打不开含中文的路径，
sidecar 会自动准备一份 ASCII 路径的副本再转发，对使用者透明。

**填写逐字稿**：两个地方都能填，写的是同一份数据（以音色库为唯一数据源）：

- **配音配置面板**（推荐）——给角色选完参考音频后，下方会直接出现逐字稿输入框，选中音色即自动带出已有稿子
- 音色库管理页 ——按音色列表逐个编辑

> 逐字稿必须与参考音频**内容完全一致**。Breeze 会把逐字稿和音频一起编码进提示，
> 不匹配会直接拉低克隆相似度。留空的音色在合成时会被 sidecar 拒绝（HTTP 400）。

**绑定音色**：在配音配置面板给每个说话角色（**含旁白**）选一个参考音频。
页面会给出响度体检（偏响的参考会让所有输出都像在喊）。

### 5. 启用提示词注入

设置面板里打开「启用提示词注入」，否则大模型不会按 `[角色][情感描述][场景]“台词”` 格式输出，
情感描述也就无从生成。

## 故障排查

| 现象 | 原因 |
| --- | --- |
| **完全没声音，控制台只有 `角色 "X" 未绑定，回退到:`** | **该角色没有绑定参考音频。** Breeze 必须知道用哪个音色，未绑定时不会用任何默认值兜底，该行会被静默跳过。打开配音配置面板，给每个说话角色（**含旁白**）都选一个音色。 |
| **改了逐字稿，重播同一楼层还是旧声音** | 插件有**两层缓存**（见下）。同一楼层已在本会话推理过就命中内存缓存，需刷新页面或对其余楼层重新推理。 |
| `音色 xxx 还没有逐字稿` | 该音色未填 `ref_text`，管理页补上 |
| 不出声、无报错 | 检查 7870 与 7881 两个服务是否都在运行 |
| 情绪没差别 | 检查 `guidance_scale` 是否为 4；确认提示词注入已启用 |
| 换情绪仍播旧音频 | 缓存键已含 `instruction`，若仍异常请清一次缓存 |

> **音色绑定按角色卡分别保存**（存储在 `voiceMap[卡片ID][角色名]`）。换一张角色卡需要重新绑定，这是上游设计。

### 关于两层缓存

| 层 | 键 | 生效范围 | 什么时候失效 |
| --- | --- | --- | --- |
| 内存 | 消息 ID（`audioCache[mesId]`） | 当前页面会话 | **刷新页面**即清空 |
| IndexedDB | 角色 + 音色文件 + 文本 + 语速 + 音量 + 情感描述 + **逐字稿** | 跨页面、跨会话 | 上述任一项变化 |

内存层在前：同一楼层本会话推理过一次，之后直接返回，**不会**再走 IndexedDB。
所以**修改逐字稿后要刷新页面**才能听到新结果；换一段新台词则立即生效。
