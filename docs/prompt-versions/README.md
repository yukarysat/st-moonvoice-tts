> **v6 → v7 只动了一句场景说明**，并新增一个内联示例（约 107 字符）：
>
> ```
> ### 场景：
> 仅从下面的列表中选择，避免自创；没有合适的就写空的方括号 []。
> 当前环境不在列表里时，场景必须写成空的方括号 []（不要用近似的词凑合）。
> 插件靠这个空括号停掉上一段环境音；不写或写错，上一个环境的声音会一直延续下去。
> 例：[小明|男-少年][语气平静，语速适中][]“我们到了。”
> ```
>
> **为什么需要这句**：环境音是循环的，只能被另一个环境音顶掉。如果模型遇到列表里没有的
> 环境而随手写一个近似词，插件找不到文件就会**让上一个环境音继续响下去**——你会听到
> 上一个场景的声音留在新场景里。
>
> **「留空能停」是实测过的，不需要改代码**（`setup/106-cdp-empty-scene.mjs`）：
>
> | 写法 | 解析出的场景 |
> | --- | --- |
> | `[ ]`（带空格） | `""` |
> | `[]` | `""` |
> | 省略第三个方括号 | 无字段 |
>
> 三种都会被 `playScene` 转成 null 并触发 `stop()`；实测环境音确实被停掉、下一句能重新起。
>
> 示例放在**场景一节里内联**，而不是加进 `## 格式示例：` 那块——那里是模型模仿最重的区域，
> 放一个空场景的完整示例行可能导致它**过度使用**空场景。等你实际用下来觉得模型不肯用 `[]`，
> 再把它提到格式示例里不迟。

> **v5 → v6 只改了「情感描述」这一段**（681 → 249 字符），场景列表、示例修正、角色规则
> 一字未动。diff 确认过，改动严格限定在该章节内。
>
> **为什么要回退**：实机试听后发现，**限制动作描写之后情感表达反而没有之前准确**。
> 这印证了当初做 v2 时留下的那条保留意见——动作描写的价值可能正是在于它携带的语境，
> 砍掉就丢了信息。所以音频这件事最终还是要听感说了算，不是规则越"干净"越好。
>
> **一个必须处理的坑**：v2 加的迁移标记 `能从声音里听出来` 就长在情感描述那一段里。
> 一旦回退，标记消失，`getSettings()` 里的守卫会认为"这还是旧版"，
> 每次加载都把整条提示词覆盖回 `index.js` 的默认值——用户的回退会被无声冲掉。
> 所以标记同步换成了回退后仍然存在的 `不要复述内容`。
> 连续重载两次验证过：内容稳定，不被覆盖。
>
> **顺带修了验收套件的一个坏味道**：原来有一条断言写死了「提示词要求情感描述只写能听出来的」，
> 那是把一次设计选择固化成了验收标准。已改成断言"情感描述要求用自然语言描述念法"这个
> 与具体措辞无关的核心适配点——否则用户每按听感调一次提示词，验收就红一次。

> **v4 → v5 只删了一条规则**：
> ~~同一场戏里选定一个就保持一致，不要在多行之间来回切换~~
>
> 撤销原因：用户计划加入 `敲门`、`电话铃`、`干杯` 这类**事件音效**，它们本来就需要即时切换，
> 这条规则会直接妨碍它们。
>
> 原本想解决的"来回切换一顿一顿"，改用**淡入淡出**处理——但排查时发现淡入淡出本身有 bug，
> 已一并修掉（见 `README-Breeze.md` 的场景音效章节）。
>
> ⚠️ **但有个前提问题尚未解决**：`index.js` 第 589 行是无条件的 `audio.loop = true`，
> 所有场景音都会**永久循环**，而且新场景会**顶替**当前环境音而不是叠加。
> 也就是说现在放 `[敲门]`，它会一直敲下去、并把房间底噪顶掉。
> 事件音效要真正可用，需要再区分一条「一次性音效」通道。

## 为什么要改

用真实回复复盘时发现：**情感描述槽位里混进了动作描写**，四行里有四行都是。

| 行 | 情感描述 | 动作占比 |
| --- | --- | --- |
| 1 | `重新端起温热的茶杯抿了一口，语调惬意舒适` | 13/20 ≈ **65%** |
| 2 | `捧着自己的茶杯小口喝着，语气中带着几分慵懒与满足` | 11/23 ≈ **48%** |
| 3 | `温和地注视着她，语速从容沉稳` | 7/14 ≈ **50%** |
| 4 | `粉瞳弯成了月牙状，甜甜地笑着，语调极其依赖温柔` | 14/23 ≈ **61%** |

规则里明明写着「只描述'怎么说'，不要复述内容」，**四条`格式示例`也全是纯表达**——示例没错、规则没错，但模型还是漂了。原因在正文这一句：

> 请**根据你对这段内容的理解**，用一句自然语言描述这句话该怎么说

「根据你对这段内容的理解」等于发了许可：面对动作密集的叙事文本，模型就去总结剧情了。
它没有复述**台词**，所以也不算违反「不要复述内容」——钻了空子。

顺带查出一个**示例自相矛盾**：`格式示例` 里用的场景是 `春日公园`，但场景列表里根本没有这一项
（列表里是 `公园氛围`）。示例在教模型"自创场景名没关系"，而规则又写着「仅在列表选择，避免自创」。

## v2 改了什么

1. **删掉「根据你对这段内容的理解」** —— 这是漂移的源头
2. **给出唯一判断标准**：只写「能从声音里听出来的」东西。可记忆、可自查
3. **列出可写的四个维度**：情绪态度 / 语气音色 / 语速节奏 / 音量气息
4. **明确禁止三类**：身体动作、外貌与表情细节、心理活动与剧情
5. **动作 → 表达的翻译指引**（关键）：
   - 「抿了一口热茶」→ 语速舒缓，尾音放松
   - 「疲惫地坐下」→ 声音发沉，气息不足，语速拖慢
   - 「甜甜地笑着」→ 语调上扬，含着笑意
   动作本身对配音没有指导意义，但它**造成的说话方式**有。所以是"翻译"，不是"删掉"
6. **逐行自查清单**：写完检查有没有「端起 / 看着 / 站着 / 走向 / 瞳孔 / 脸颊」这类词
7. **修正示例场景名**：`春日公园` → `公园氛围`（列表内的合法项）
8. **补一条女角色示例**，示范"表达优先"的写法

角色规则、格式定义、场景列表、`内容` 的写法**一律没动**。

## 自动升级是怎么做的

先分清两件事：**没有「按版本号覆盖」这种机制**。`getSettings()` 用 `deepMergeDefaults()`
合并默认值，而它只补**缺失的键**（`if (!Object.prototype.hasOwnProperty.call(target, key))`），
所以已经存过的 `promptInjection.content` 不会被新版本悄悄换掉。

真正会动用户提示词的是另一段**内容判定**，它在**每次读设置时**都跑（不只是更新后第一次）：

```js
const NEW_MARK = '不要复述内容';
const OURS = ['格式输出规范', '情感描述', '角色名'];
if (!inj.content.includes(NEW_MARK) && OURS.every(k => inj.content.includes(k))) {
    inj.content = defaultSettings.promptInjection.content;   // ← 整段替换
}
```

两个条件**同时**成立才会覆盖：内容里**没有**最新标记，**且**内容里同时有那三个小标题。
于是实际行为是：

| 输入 | 结果 |
| --- | --- |
| 旧版默认提示词 | 升级为当前版本（就是它要干的事） |
| 当前默认提示词 | 不动（幂等） |
| 完全自己写的提示词 | 不动 —— 除非你恰好也用了那三个小标题 |
| **在默认提示词上改、但把 `不要复述内容` 删掉了** | **会被整段替换掉**，且不是「更新时」才发生，而是下次读设置时就发生 |

最后一行是这个机制的真实边界，`OURS` 那道防线挡不住它：用户明明是在改自己的提示词，
只要改动中不巧抹掉了那个标记，就会被判为「这是旧默认值」。旧版守卫只判断「缺标记」时
这个问题更宽，加了 `OURS` 之后窄了很多，但没有消除。

> **标记本身还会随版本更换。** 历史上是 `能从声音里听出来`（v2 加），v6 回退时换成了
> `不要复述内容`——因为前者长在「情感描述」那一段里，回退时会被删掉，标记一消失守卫
> 就会每次重载都把提示词覆盖回默认值，用户的回退被无声冲掉。**每换一次标记，就有一批
> 「改了默认提示词但保留着旧标记」的用户进入上面最后一行的处境。**
>
> 想彻底根治，需要给「用户手动保存过」这件事留一个持久标记（例如面板保存提示词时写
> `userEdited = true`，守卫遇到它就永不覆盖），而不是靠猜内容。目前**没有**实现。

三种典型输入的实际行为都验证过：

| 输入 | 结果 |
| --- | --- |
| 旧默认提示词 | 升级到当前版本 |
| 当前默认提示词 | 不动（幂等） |

## 怎么回退

1. 把 `prompt-v1-备份.md` 的内容整段粘进插件设置面板的「提示词内容」框
2. 升级守卫不会再覆盖它——因为 v1 里没有新标记，但**有**那三个小标题，所以下次加载仍会被判定成旧默认值而升级

> 所以要长期停在 v1，得在 v1 文本里删掉任一个固定小标题（如 `格式输出规范`），
> 或者干脆把 `promptInjection.enabled` 关掉。
> 更省事的办法是告诉我，我把 `index.js` 的默认值改回去。
