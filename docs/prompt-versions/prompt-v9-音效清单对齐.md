# v9 默认值与在用版本对齐（默认提示词）

本文记录**默认提示词**（`index.js` 里 `defaultSettings.promptInjection.content`）的最后一次改动。

## 背景：默认值和实际发的资源对不上

默认提示词只在**全新安装**与**迁移**时生效——已经生效过的提示词以
`settings.json` 里的那一份为准（见 [自动升级是怎么做的](README.md#自动升级是怎么做的)）。
所以作者本机一直没暴露这个问题：本机生效的提示词早就被手工改过好几轮了，
和 `index.js` 里的默认值完全是两回事。

真正的用户是**全新安装的人**：他拿到的默认值里，「正常场景列表」还是照着
早期音频目录写的 16 个名字（`乡村_清晨`、`公园氛围`、`厨房_切菜`…），
而随整合包发布的 `data/pjy/` 里是**另一批 9 个文件**。两边只有
`沙滩_海浪` 和 `雨声_室内` 重合 —— 也就是说，他即使装齐了整合包和插件、
也开了提示词注入，模型照着清单写出来的场景名**基本找不到文件，场景音效等于没有**。

## 改了什么

**默认值直接采用作者本机正在生效的那一份提示词**，只改「正常场景列表」这一行：

| | 内容 |
| --- | --- |
| 改前（16 个） | `乡村_清晨` `公园氛围` `海滨城市氛围` `夏季氛围` `城镇闹市` `沙滩_海浪` `海鸥_鸣叫` `脚步_沙滩` `雨声_室内` `雨声` `雨声_滴在雨伞上` `厨房_切菜` `厨房_煎食物` `浴室_淋浴` `脚步声木地板` `脚步声_跑步` |
| 改后（9 个） | `乡村_傍晚` `森林` `森林_清晨` `森林_起风` `沙滩_海浪` `瀑布` `雨声` `雨声_室内` `房间_开门` |

改后的 9 个名字与**整合包 `data/pjy/` 里的文件一一对应**（8 段循环环境音 + 1 段一次性事件音）。
提示词里这 9 个名字写在**同一份清单**里，不区分循环与一次性——插件按名字查文件，
播放行为由文件所在的子文件夹决定，提示词不需要知道这件事。

清单之外还有第二个列表，**标题保留、内容留空**，留给使用者按自己的音频自行填写。

**其余部分一字未动**：格式说明、角色名与 `性别-年龄段` 标签、情感描述的要求、
格式示例、以及「这一节只是资源清单，与剧情无关」那段话，全部与作者本机生效的版本逐字一致。

## 为什么这次改动很小却重要

这是**适配问题而不是提示词问题**：措辞、示例、规则都没错，错的是默认值里那份
资源清单指向了一个已经不存在的音频集合。改的是清单，不是设计。

按听感/实际文件校准清单这件事本身是 v3、v4 就在做的（v4 就干过一次
「正常场景列表 7 → 16 个，补齐 `pjy/` 里实际存在的文件」）。v9 只是把同一步
重新做了一遍——因为中间发布形态变了：音效从「作者本机目录」变成了「整合包内固定 9 个文件」。

## 对已有用户的影响

**没有影响。** `getSettings()` 的迁移守卫要求「内容里没有 `不要复述内容`
且同时含 `格式输出规范` / `情感描述` / `角色名` 三个小标题」才会覆盖，
而 v2 之后的提示词全都带这个标记。只有两种情况会拿到新的默认值：

- 全新安装
- 提示词还是 v1 时代的旧默认值（本来就会被升级）

自己改过提示词的人不会被碰。守卫的标记与三个小标题这次都没有改动，
改动严格限定在文末的清单行，所以这个幂等判断的行为不变。

> 顺带修了一处日志失真：`index.js` 里迁移成功时打印的是
> `提示词已升级到 v2：情感描述只写「能从声音里听出来的」`。
> 这条日志从 v2 起就没再更新过，实际早就迭代到 v9 了，留着比不写更误导。
> 已改成不带版本号的「默认提示词已升级到当前版本」。

## 自己加音效时怎么改

把音频丢进 `<数据目录>/pjy/环境音效/`（循环）或 `<数据目录>/pjy/事件音效/`（只响一次），
再把「正常场景列表」改成对应的**文件名（去扩展名）**即可。同名时 `环境音效/` 优先于 `pjy/` 根目录。

插件**不校验**名字，写错只会静默无声、不会报错——这是排查场景音效时最容易被忽略的一点。
详见主 README 的[场景音效的目录约定](../../README.md#场景音效的目录约定)。
